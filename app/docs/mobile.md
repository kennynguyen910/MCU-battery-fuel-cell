# Android and iOS

## Shared Dart app

lib/main_mobile.dart launches the collector explicitly. lib/main.dart also
launches the collector on native platforms and the history viewer on web.
lib/screens.dart contains the widgets, lib/api.dart the HTTP client, and
lib/capture_log.dart the save-before-upload logic.

The host projects are generated by Flutter, using standard Android Kotlin and
iOS Swift bootstrap files. Business logic remains Dart. Those host languages,
Java/Gradle, and Xcode are platform build prerequisites, not additional app
frameworks.

## Android on this PC

Flutter, Java, Android SDK, and an Android 36 emulator image are installed.
The emulator name is Capstone_Test. The installed APK uses
com.example.capstone_monitor, a development application ID.

From the repository root:

```powershell
.\dev.cmd android
.\.tools\android-sdk\emulator\emulator.exe -avd Capstone_Test
```

After the emulator boots:

```powershell
cd apps/monitor
..\..\.tools\flutter\bin\flutter.bat run -d emulator-5554 -t lib/main_mobile.dart --dart-define=API_URL=http://10.0.2.2:3001
```

The emulator maps 10.0.2.2 to the host PC. The APK is a debug build, not a store
release. Android's debug manifest permits HTTP for local bench testing; the
main manifest declares Internet access. Release builds should use HTTPS.

## A physical Android phone

Enable developer USB debugging on your own phone and authorize the development
computer when Android asks. Run flutter devices to identify it and use that
device ID with flutter run. For USB testing, adb reverse tcp:3001 tcp:3001 lets
the app use http://localhost:3001. Alternatively, use the PC's reachable LAN
address in the app's API-address field. This task has not opened firewall ports.

Keep the app foregrounded during capture. Do not expect a suspended app to poll.
The local log is app-private capstone-log.json in the documents directory.
View local log displays it without needing a file browser.

## iOS on a Mac

This repository includes ios/Runner.xcworkspace and the native Flutter host.
Windows cannot run Xcode, the iOS compiler, or the iOS simulator. A Mac build
and signing step remains necessary; no iOS binary is claimed here.

1. Copy the source to a Mac with Flutter and Xcode configured.
2. Run flutter doctor and resolve its iOS toolchain requirements.
3. In apps/monitor, run flutter pub get.
4. For a simulator, start it and run:

```sh
flutter run -d <simulator-id> -t lib/main_mobile.dart --dart-define=API_URL=http://<api-host>:3001
```

5. For an unsigned compilation check: flutter build ios --debug --no-codesign
   -t lib/main_mobile.dart.
6. For a physical iPhone, open Runner.xcworkspace in Xcode, select your signing
   team and an appropriate unique bundle identifier, then run on your device.

Info.plist describes local-network access and allows local networking. iOS may
ask the user to grant local-network access. Prefer an HTTPS API; do not disable
transport security globally to work around network configuration.

## Hosting later

Vercel can serve the Flutter web output. AWS will host Node/Express and Postgres.
Use --dart-define=API_URL=https://your-api-host at web build time, or the app's
API-address field for testing. No cloud account, payment, credentials, or
deployment has been created by this local setup.
